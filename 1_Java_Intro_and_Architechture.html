What is Java?

Building the mental model before the definition

📘 Formal Definition

Java is a high-level, object-oriented, class-based programming language designed to be portable, robust, secure, and suitable for building applications ranging from backend services to enterprise systems.

✉️ Real-Life Analogy: Writing a Letter

What a human writes

The computer ultimately understands only machine instructions. Java provides a layer between human-readable programming and machine execution — so developers write in a readable language, and Java handles the translation down to the machine.

🚫
A common misconception I want to clear up: people often say "Java means Write Once, Run Anywhere — so it just runs directly everywhere." That's not quite accurate, and I don't want you carrying that half-truth forward.
✅
Here's how I want you to actually understand it: Java source code is compiled into bytecode, and a compatible JVM executes that bytecode on the target platform. Portability comes from the JVM layer, not magic — remember that distinction.

First Java Program

Starting from absolute zero — write, compile, run

HelloWorld.java 
public class HelloWorld {

    public static void main(String[] args) {

        System.out.println("Hello, Java!");

    }
}
Console OutputHello, Java!

🔍 Line-by-Line Explanation

public
Access modifier — controls visibility of the class.
class
Keyword that defines a class — the basic building block of a Java program.
HelloWorld
The class name — must match the file name (HelloWorld.java).
main()
The starting point of a traditional Java application. Execution begins here.
System.out.println()
Prints information to the console.

🛠️ Step-by-Step: Compile & Run

Create the source file

Save the code above in a file named exactly HelloWorld.java. The file name must match the public class name.

Compile with javac

Run javac HelloWorld.java in the terminal. This invokes the Java compiler.

Bytecode file is generated

The compiler produces HelloWorld.class — the bytecode version of your program.

Run with java

Run java HelloWorld (no .class extension). The JVM loads and executes the bytecode.

Observe the output

The console prints Hello, Java! — confirming the full source → bytecode → execution pipeline worked.

JDK vs JRE vs JVM

The most commonly asked interview distinction

🍽️ Restaurant Analogy

JDK — Complete Restaurant
Includes everything: kitchen, dining area, AND the chefs / tools to prepare new dishes (development tools).
JRE — Kitchen + Dining Facilities
Everything needed to serve an already-prepared dish (run an app) — but no tools to create new recipes.
JVM — The Kitchen
Where the actual cooking (execution) happens — bytecode goes in, running behavior comes out.

JVM

  • Runs Java bytecode
  • Provides the execution environment

JRE (historically)

  • JRE = JVM + Runtime Libraries
  • Enough to run a compiled Java app

JDK

  • JDK = Development Tools + Runtime
  • Everything needed to write, compile, and run Java
💡
A quick modern note: in practice, you won't usually install a JRE separately anymore. That standalone-JRE model I described above is mostly historical — today you'll simply install a JDK and it covers both development and running your programs.
